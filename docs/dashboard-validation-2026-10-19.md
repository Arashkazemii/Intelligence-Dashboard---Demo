پاسخ‌های موفق بالا دو فراخوانی داشتند. یک اجرای تشخیصی حمل سه فراخوانی داشت: مدل ابتدا
composed سه‌سری نامجاز پیشنهاد کرد؛ validator رد کرد؛ خود مدل آن را به دو سری معتبر با
محورهای مستقل اصلاح کرد. هیچ داشبورد ثابت یا تحلیل ساختگی جای خطا قرار نگرفت.

در تلاش‌های اولیهٔ نسخهٔ جدید، نمای کلی و پل به‌خاطر عدد آزاد و حمل به‌خاطر ترکیب برنامهٔ
داده یا layout نامعتبر رد شدند. این شواهد به اصلاح prompt، خطای دارای مسیر فیلد و فرصت
اصلاح محدود مدل منجر شد. پس از اصلاح، نمای کلی و حمل دوباره از API عمومی موفق شدند؛
حمل مستقیماً از فرم UI نیز با GapGPT واقعی موفق شد. در این اجرای واقعی 503 provider
دیده نشد؛ نباید خطاهای قرارداد 502 را اختلال موقت سرویس نامید. 503 و timeout در تست‌های
جدا شبیه‌سازی و از خطاهای قرارداد تفکیک شدند؛ احراز هویت provider و رد قالب درخواست نیز
کد و پیام مجزا دارند.

## آزمون، build و Docker

- پایهٔ قبلی: ۲۶ تست موفق.
- suite نهایی: **۹۲ passed، یک warning، ۲٫۵۷ ثانیه**؛ unit/schema/adversarial و تست‌های
  محاسبات/API روی سه دیتابیس PostgreSQL موقت و مستقل. warning مربوط به deprecation
  اتصال Starlette TestClient/httpx است؛ تستی skip نشده است.
- هر ۱۲ نوع registry هم نمونهٔ معتبر و هم قواعد رد نامناسب دارند. پوشش شامل درصد با
  مخرج صفر/نامعتبر، دادهٔ ناقص، کل ناسازگار، زمان تکراری، منفی‌های area/pie، محور ناسازگار،
  bridge ناسازگار، فیلد/ارجاع ناموجود، عدد آزاد و حروفی، قطعات اجرایی، parser، timeout،
  سقف چرخهٔ تکمیلی و اصلاح محدود مدل است.
- frontend: `npm ci` از lockfile موجود در Docker؛ `npm run build` شامل `tsc -b && vite build`
  موفق. تلاش `npm ci` میزبان در این محیط بدون پیشرفت شبکه متوقف شد؛ build معتبر در Docker
  انجام شد. `package.json` و `package-lock.json` تغییر نکردند.
- API و web با Docker Compose build و اجرا شدند؛ `db/api/web` هر سه healthy هستند.
- محیط `dashboard-validation` فقط tmpfs داشت؛ پس از تست بسته شد. دیتابیس اصلی seed نشد.
- گراف محلی فقط از کد بازسازی شد: ۸۶۸ node و ۲۰۰۶ edge، بدون semantic API. یک فایل SQL
  به‌علت نبود `tree_sitter_sql` AST نداشت؛ schema و SQLهای مربوط مستقیماً بررسی شدند.

## مرورگر و نمودارها

Chrome نصب‌شده، Playwright CLI، viewportهای `1440×1000` و `390×844`.
نشست‌های ساخته‌شده برای آزمون بسته شدند. screenshotها پس از بارگذاری صریح assetهای
جدید بررسی بصری شدند؛ ثبت screenshot به‌تنهایی معیار موفقیت نبود.

`scripts/check_renderer_browser.js` دوازده renderer را با fixture اعتبارسنجی‌شدهٔ دادهٔ
واقعی دیتابیس آزمایش کرد: line، area، bar، horizontal_bar، grouped_bar، stacked_bar،
composed، pie، donut، radial، waterfall، radar. وجود SVG و هندسهٔ داده، عدم overflow و
خطای runtime کنترل شد. چهار تصویر registry در `artifacts/dashboard-v2-registry-*` هستند.
رنگ سیاه ناشی از شناسهٔ SVG فارسیِ فاصله‌دار در pie/radial پیدا و با شناسهٔ داخلی ASCII
رفع شد. bar افقی نزولی مرتب می‌شود و برچسب فارسی آن از نمودار بیرون نمی‌زند.

radar فقط در fixture شاخص‌های واقعی نرمال‌شدهٔ فصل دوم برابر صد بررسی شد؛ مدل در سؤال‌های
نمونه به آن نیاز نداشت. area، horizontal_bar، stacked_bar، pie، donut و radial نیز در
registry قابل استفاده‌اند؛ در آخرین پاسخ‌های نمونه صرفاً برای تنوع اضافه نشدند. Sankey
به‌علت نبود جریان واقعی عرضه نشده؛ scatter، heatmap و treemap نیز در قرارداد نیستند.

سؤال حمل از فرم واقعی UI، بدون route mock، پاسخ composed و line گرفت. همان پاسخ در
موبایل نیز بررسی شد. تصاویر `dashboard-v2-live-shipping-*` ثبت همین اجرای مستقیم‌اند.
جدول و مسیر منبع هزینهٔ حمل فصل سوم تا جمع دقیق **۹٬۰۰۰٬۰۰۰٬۰۰۰ تومان** تطبیق داشت؛
tooltip مقدار و واحد هر دو محور را درست نشان داد. انتقال focus و scroll به جزئیات منبع
و reduced motion رعایت شد. خطا و warning مرورگر در بررسی نهایی صفر بود.

`scripts/check_sample_browser.js` پاسخ‌های ثبت‌شدهٔ واقعی هشت سناریو را نیز برای پوشش UI
بازپخش می‌کند؛ این بازپخش مصرف مدل ندارد و از آزمون مستقیم فرم و از fixture پوشش renderer
تفکیک شده است.
