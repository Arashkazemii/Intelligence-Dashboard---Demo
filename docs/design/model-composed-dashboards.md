# داشبورد متناسب با پرسش، قرارداد نسخهٔ ۲

مبنای تغییر: کامیت محلی `4b1386c0a74f90a7efc305928012cc3289d97906`.

## اشکال معماری قبلی

`questions.py` فقط یک `Plan` شامل `intent/metrics/periods/category/view` از مدل می‌گرفت.
مدل کاتالوگ را می‌دید، ولی هیچ دادهٔ واقعی دریافت نمی‌کرد. سپس `execute()` گزارش کامل را
می‌خواند و متن، پنج widget نمای کلی و یک insight ثابت را انتخاب می‌کرد. رابط نیز همین
widgetها را به اجزای گزارش نمونه تبدیل می‌کرد. گزارش مدیریتی یا قوت و ضعف قرارداد مستقلی
برای تحلیل و ترکیب نداشت؛ تکرار نمای کلی پیامد مستقیم همین طراحی بود.

فیلتر `category=shipping` فقط با `intent=metric`، شاخص `opex` و یک دوره مجاز بود.
ترکیب حمل با داشبورد، روند یا مقایسه رد می‌شد. درخواست واقعی «داشبورد حمل بده» در مبنا
با HTTP 502 و «ترکیب نیت و نمایش مدل نامعتبر است» بازتولید شد. frontend نیز همهٔ 502ها
را به «پاسخ مدل نامعتبر بود» تبدیل می‌کرد؛ دلیل واقعی پنهان می‌شد.

## جریان جدید و مرز مسئولیت

1. `POST /api/demo-finance/question` سؤال فارسی را می‌گیرد.
2. مدل با کاتالوگ محدود، `DataPlan` شامل پرس‌وجوهای ساختاریافته می‌سازد: شناسه، متریک،
   دوره، بعد و فیلتر مجاز. هیچ SQL، کد، نام جدول یا renderer option پذیرفته نمی‌شود.
3. `DataBuilder` خواندن‌های فقط‌خواندنی و پارامتری را انجام می‌دهد. محاسبات با `Decimal`
   انجام می‌شوند. datasetهای کوچک و factهای دارای تعریف، واحد، دوره، مقدار دقیق،
   شناسهٔ سطر منبع و فیلتر drilldown تولید می‌شوند. دادهٔ ناموجود با صفر تفاوت دارد.
4. مدل سؤال، دستور طراحی، دادهٔ خوانده‌شده، factها، schema و کاتالوگ نمودارها را می‌بیند.
   می‌تواند یک بار دادهٔ تکمیلی از همین قرارداد بخواهد؛ سپس باید spec نهایی بسازد.
5. مدل عنوان، پاسخ مستقیم، اجزا، نوع نمودار، dataset و سری، ترتیب و عرض اجزا، جدول‌ها
   و اولویت بینش‌ها را انتخاب می‌کند. داشبورد از preset یا intent ثابت انتخاب نمی‌شود.
6. backend schema، شناسه‌ها، چیدمان، فیلدها، واحدها، نمودار و ارجاع‌های عددی را اعتبارسنجی
   می‌کند. متن مدل از `{{fact_id}}` استفاده می‌کند؛ عدد یا درصد آزاد رد می‌شود. مقدار
   نهایی را backend از fact معتبر جایگزین می‌کند. فرمول دلخواه مدل اجرا نمی‌شود.
7. React ترتیب `DashboardSpec.layout` را رندر می‌کند. registry بسته، ChartSpec را به
   props کنترل‌شده تبدیل می‌کند. متن React escape می‌شود؛ HTML/JSX/SQL اجرا نمی‌شود.

مدل انتخاب و روایت می‌کند؛ backend دسترسی، عدد، محاسبه و اعتبار قرارداد را تعیین می‌کند.
کل درخواست حداکثر سه فراخوانی مدل و ۱۱۰ ثانیه مهلت دارد؛ هر فراخوانی حداکثر ۴۰ ثانیه.
اگر برنامهٔ داده یا spec رد شود، فرصت باقیمانده می‌تواند صرف اصلاح توسط همان مدل شود.
اصلاح، داده و خطای اعتبارسنجی را دوباره به مدل می‌دهد؛ داشبورد جایگزین قطعی نمی‌سازد.
اصلاح و دریافت دادهٔ تکمیلی از همان سقف سه فراخوانی استفاده می‌کنند. حداکثر یک چرخهٔ دادهٔ
تکمیلی مجاز است. سقف‌ها: هشت query در مجموع، صد ردیف، دویست‌وپنجاه fact، ۵۸ کیلوبایت
متن داده در هر درخواست مدل، ۶۴ کیلوبایت پاسخ و ۱۴۰۰/۵۲۰۰ توکن خروجی برنامه/ترکیب.
اعتبارسنجی ارجاع عددی جای اثبات معنای آزاد زبان طبیعی را نمی‌گیرد؛ روایت تجاری همچنان
به شواهد مستقل نیاز دارد. قواعد prompt و رد ادعای علّی قطعی این محدودیت را آشکار می‌کنند.

خطاها تفکیک شده‌اند: قطع/اشباع سرویس مدل، تنظیمات یا احراز هویت provider، timeout، JSON
نامعتبر یا بریده‌شده، schema نامعتبر، نوع نمودار نامجاز، دادهٔ ناکافی، ارجاع و ادعای عددی
نامعتبر و دسترسی دیتابیس. UI پیام فارسی backend را نگه می‌دارد. لاگ فقط مرحله، کد، مسیر
فیلد و وضعیت HTTP را ثبت می‌کند؛ کلید، header، متن سؤال یا بدنهٔ پاسخ مدل در لاگ نیست.

## داده و معنا

داده‌ها ساختگی‌اند، ولی از PostgreSQL فعلی خوانده می‌شوند؛ مدل عدد نمایشی تولید نمی‌کند.
بازه: آوریل تا سپتامبر ۲۰۲۶، تاریخ ثبت، منطقهٔ زمانی `Asia/Tehran`. مبالغ پایه تومان؛
نمودارها میلیارد تومان، درصدها و شاخص‌های نرمال‌شده با واحد صریح‌اند.

متریک‌ها: درآمد، بهای کالا، هزینهٔ عملیاتی، سود عملیاتی و دسته‌های حمل، حقوق و اداری.
ابعاد: دوره، دستهٔ هزینه، مرکز هزینه، پل سود و شاخص نرمال‌شده. شناسه و تعریف منبع در
پاسخ نگه داشته می‌شوند. برگشت و اصلاح سند در دورهٔ ثبت خود محاسبه می‌شوند؛ اصلاح ثبت‌شده
در سپتامبر به‌صورت بازنویسی ژوئن معرفی نمی‌شود.

در دادهٔ فعلی حمل فقط مرکز «عملیات» دارد. مسیر، مسافت، تعداد محموله، مشتری، بودجه، هدف
و علت تجاری مستقل موجود نیست. تغییر سود یک تطبیق حسابداری است؛ دلیل تجاری افت سود نیست.

## نمودارهای قابل استفاده

| نوع | داده و محدودیت |
|---|---|
| line / area | دست‌کم سه ماه مرتب و متمایز؛ مساحت چندسری فقط اجزای جمع‌شوندهٔ غیرمنفی |
| bar | یک سری عددی برای مقایسهٔ دسته یا دوره |
| horizontal_bar | رتبه‌بندی دسته‌ها، مناسب برچسب بلند فارسی |
| grouped_bar | چند سری هم‌واحد و قابل مقایسه |
| stacked_bar | فقط اجزای هزینهٔ جمع‌شونده؛ کل در کنار اجزای خودش پذیرفته نمی‌شود |
| composed | فقط جفت متریک مرتبط؛ واحد متفاوت با محور دوم صریح |
| pie / donut / radial | دو تا شش جزء غیرمنفی، کل مثبت و تطبیق‌یافته؛ کمان radial نسبت به همان کل |
| radar | فقط شاخص‌های نرمال‌شده با مبنای مشترک؛ مقادیر خام پذیرفته نمی‌شوند |
| waterfall | فقط دادهٔ پل با ابتدا، تغییرهای علامت‌دار و انتهای تطبیق‌یافته |

از [مستندات رسمی EvilCharts](https://evilcharts.com/docs) و
[فهرست Recharts](https://evilcharts.com/docs/recharts/components) استفاده شد. نسخهٔ Recharts
با dependency موجود پروژه سازگار است. اجزای area، composed، radial و radar از registry
رسمی به اجزای محلی موجود اضافه شدند؛ مجوز MIT و منشأ در README اجزا ثبت شده است.
dependencyهای موجود، از جمله Recharts و Motion، حفظ شده‌اند؛ موتور دوم اضافه نشده است.

EvilCharts کامپوننت waterfall مستقیم ندارد. bridge موجود گزارش نمونه حفظ شده؛ renderer
پویا از range bar معتبر Recharts با همان ChartSpec و کنترل تطبیق استفاده می‌کند.

[Sankey رسمی](https://evilcharts.com/docs/recharts/sankey-chart/static) بررسی شد؛ چون دادهٔ
گره و جریان واقعی نداریم، در registry اجرایی یا کاتالوگ انتخاب مدل قرار نگرفت. scatter،
heatmap و treemap نیز عرضه نمی‌شوند. نمودار صرفاً برای تنوع بصری افزوده نمی‌شود.

## آزمون و تکرارپذیری

تست‌های schema، محاسبات، انتخاب و رد نمودار، اعداد و ارجاع نامعتبر، parsing، خطاهای
سرویس و چرخهٔ تکمیلی در `backend/tests` قرار دارند. محیط زیر PostgreSQL موقت با tmpfs
می‌سازد و هیچ volume دیتابیس پروژه را mount نمی‌کند:

```powershell
docker compose -p dashboard-validation -f compose.validation.yaml build tests
docker compose -p dashboard-validation -f compose.validation.yaml run --rm tests
docker compose -p dashboard-validation -f compose.validation.yaml down
```

آزمون زنده فقط با اجرای صریح انجام می‌شود و مصرف سرویس مدل دارد:

```powershell
python scripts/check_live_dashboards.py --base http://127.0.0.1:8081 --output .local/live
```

`scripts/export_chart_fixture.py` برای پوشش renderer، دادهٔ واقعی دیتابیس را فقط می‌خواند
و دو spec اعتبارسنجی‌شده با دوازده نوع نمودار صادر می‌کند. ترکیب این fixture را مدل انتخاب
نکرده؛ بررسی آن مکمل آزمون پرسش‌های واقعی است و در مسیر محصول استفاده نمی‌شود.

نتایج این اجرا، ترکیب هر سؤال، محدودیت‌های سرویس و شواهد مرورگر در
`docs/dashboard-validation-2026-10-19.md` ثبت می‌شوند.
